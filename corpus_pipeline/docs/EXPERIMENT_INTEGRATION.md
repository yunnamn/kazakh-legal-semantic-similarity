# Preserve the original semantic-similarity experiment

## Integration is pending, not silently assumed

No original model, data loader, metric, pooling rule, gold annotation file or README
was obtained. This toolkit therefore does not invent a path such as `train.py` and
claim to patch it. Its output boundary is a validated JSONL or text/provenance view.
Actual loader wiring and end-to-end comparison need the inspected original checkout.

Keep the original experiment as an immutable reference worktree. Add this toolkit
on a separate integration branch only after inspection. `--repo-root` in the corpus
commands points at the frozen reference, not a moving branch where adding new
tracked files would invalidate the audit. Freeze a new audit deliberately when the
approved reference design changes; never edit a lock to suppress the check.

## Required review form

Run `audit-repo` and `experiment-review-template`. Complete:

* Actual reviewer, timezone-bearing review date, exact inventory hash and per-file
  status/evidence. The autogenerated status is `not_reviewed`.
* `reconstructed_design`: actual research question, model conditions, training/token
  budgets, seeds, similarity function/pooling, metrics, annotation scheme, pair
  sampling, checkpoint selection and evaluation roles.
* `preserve_original_semantic_evaluation=true` only after verifying that claim.
  Set `accepted_corpus_config_sha256` to the reviewed config hash, not a guessed value.
* `protected_evaluation`: existing held-out pair artifacts with `path`, `format`,
  `role` (`semantic_test`, `semantic_validation`, `annotation_holdout`), original
  `id_field`, at least two `text_fields`, optional explicit source `family_fields`.

An illustrative **schema**, not an assertion about this repository's files:

```json
{
  "path": "ACTUAL_EXISTING_PAIR_FILE.csv",
  "format": "csv",
  "role": "semantic_test",
  "id_field": "ACTUAL_EXISTING_PAIR_ID_COLUMN",
  "text_fields": ["ACTUAL_LEFT_TEXT_COLUMN", "ACTUAL_RIGHT_TEXT_COLUMN"],
  "family_fields": []
}
```

Family fields, when available, must contain explicit `adilet:<ID>` or `zan:<ID>`,
not document titles. If the original pair artifact has no IDs, duplicate IDs or
missing endpoints, investigate and document the necessary provenance repair in a
separately versioned mapping. Do not silently relabel, drop pairs or manufacture
scores to satisfy the guard. Other pair formats may need an inspected, auditable
adapter; the delivered CSV/JSON/JSONL/optional Parquet adapters are explicit.

## Corpus-only intervention contract

Preserve original model/checkpoint/tokenizer choices, pooling, similarity function,
original pair identities/labels, annotation instructions and primary metrics unless
a confirmed defect requires a separately documented correction. Retain old inputs,
results and code as the historical comparison. An authentic-source corpus changes
the adaptation population; do not describe the old and new corpora as identical.

After validation, adapt the actual existing loader to one explicit role at a time.
The exported files are:

| Role | Permitted scientific use |
|---|---|
| `train` | MLM/domain adaptation input |
| `validation` | MLM checkpoint/hyperparameter selection under the original reviewed protocol |
| `mlm_test` | Final held-out MLM diagnostic; never checkpoint selection |
| `annotation_pool` | Source material for the existing human semantic-similarity annotation workflow; never adaptation input |

The preexisting semantic evaluation remains a separate frozen artifact and is never
regenerated from `annotation_pool`. A new corpus may eventually support new human
annotations, but those require the existing protocol and separately versioned labels,
not generated scores. If original roles differ, resolve that openly in the review
rather than relabel old test examples as validation.

Do not concatenate all files in a data directory, do not run another row-random split
inside the trainer, and do not pack MLM sequences across split boundaries. Preserve
sentence IDs or line-aligned lineage through tokenization/packing. Record tokenizer
revision, sequence length, overlap/stride, token counts, truncation rate, model seeds,
optimizer/scheduler, steps/epochs, effective batch size, checkpoint criterion and
selected checkpoint. These are training integration responsibilities, not reported
as measured by a regex-word corpus statistics script.

## Comparisons without changing the research question

A defensible corpus intervention should retain the original baseline condition and
report the authentic-source condition with matched token/compute budget when feasible.
The precise design must come from the actual project. Added ablations or robustness
checks should be named as additions, not substituted for original results. Never
select a corpus filter, overlap threshold, seed or checkpoint based on final semantic
test improvement. Predeclare these decisions, keep a decision log and report exclusions.

Original gold data can itself contain source overlap or other deficiencies. Detecting
one is not permission to silently change the benchmark. Preserve reported original
scores and, when appropriate, publish a separately named decontaminated sensitivity
analysis with explicit differences and uncertainty. Repeated-pair dependence also
matters for confidence intervals; the proper resampling unit depends on the actual
annotation/source graph and cannot be determined without those files.

## Optional MLM helpers, not an unverified replacement

`kazlegal_corpus.mlm.fixed_mlm_mask` creates deterministic token corruptions keyed by
example ID, position and seed. It excludes padding and special tokens. It does not
emit new corpus prose. Reuse the same tokenizer/features/mask manifest to compare
checkpoints under one tokenizer. Across different tokenizers, token NLL is not directly
comparable merely because raw held-out documents are the same.

`aggregate_masked_losses` expects `(SUM_OF_TOKEN_NLL, MASKED_TOKEN_COUNT)` for each
batch and aggregates by masked tokens, not unweighted batch means. Its exponential
is explicitly named a masked-token diagnostic, not autoregressive perplexity.
Integrating either helper requires auditing the existing trainer; no existing masking
bug or invalid result is asserted. Neither helper changes the semantic-similarity
metric or replaces human labels.
